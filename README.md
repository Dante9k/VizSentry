# VizSentry

在 Windows 本机通过浏览器，把飞书多维表格里的图片与同一行日志一起分析。成功导入 N 条记录，结果和 Excel 主表就保留 N 行；空值、图片损坏、登录过期和模型失败都显示在原行。首版为本机单用户应用，结果不写回飞书。

## 启动

首次克隆后，先按下面的步骤运行 **`setup.ps1`**，安装依赖、构建网页并准备 Chromium 与 BRISQUE 权重；这些本机构建产物不包含在 Git 仓库里。

完成安装后双击 **`start.cmd`**，浏览器访问 <http://127.0.0.1:8765>。保留启动窗口，按 Ctrl+C 停止；重启后可在任务列表继续已导入的任务。已经完成安装的本机目录可以直接启动。

全新环境需要 Python 3.12+、Node.js 20.19+（或 22.12+）、pnpm。已验证的 Python 版本为 3.12。PowerShell 在项目目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\start.cmd
```

安装阶段需要网络，包含 CPU PyTorch、Chromium 和经过 SHA-256 校验的 BRISQUE 权重。`setup.ps1 -SkipModels` 可跳过 BRISQUE，基础图片指标仍可用；`-SkipBrowser` 会使扫码和浏览器日志读取不可用。安装脚本优先使用 PATH 的运行时，也兼容本机 Codex 捆绑运行时。

```powershell
# 自定义端口/数据目录；安装和启动应使用同一个目录
.\setup.ps1 -DataDir D:\VizSentryData
.\start.ps1 -DataDir D:\VizSentryData -Port 8765 -NoBrowser
```

启动脚本默认把数据放在项目的 `.data/`，可通过 `-DataDir` 或 `VIZSENTRY_DATA_DIR` 修改。直接运行 `python -m vizsentry` 且未设置该环境变量时，默认位置为 `%LOCALAPPDATA%\VizSentry`。网页“连接诊断”显示实际路径。

## 第一次使用

1. 点击“运行演示”，用 6 条本机样例验证多图、缺图、空日志和损坏图片的展示。演示不调用外部模型。
2. 在设置中填写支持视觉输入的 OpenAI 兼容接口地址、API Key、模型名称与业务异常标准，保存后做连接测试。测试会发送一张小型合成图片。
3. 新建任务，输入飞书链接、选择接入方式和范围，读取字段后选择图片列与日志列。链接包含多个数据表时选择目标数据表。
4. 检查预览、记录数与范围后启动。清单完整读取和校验结束才开始分析。任何无法确认完整性的导入都会明确失败，不会把部分结果称为全表完成。
5. 在结果列表看图片、逐图结论、离线证据、日志摘要；点击日志查看全文或下载原始内容。任务支持暂停、继续、取消和失败行重试。

三种接入方式均已实现，但目前没有真实样表，**尚未在你的飞书租户完成实表验收**。

| 方式 | 操作 | 主要要求 |
| --- | --- | --- |
| 应用凭证 | 在设置保存 App ID / App Secret，读取字段和记录 | 应用具有记录/字段读取、附件下载权限，并获得目标表访问授权 |
| 扫码＋连接器 | 登录飞书；在应用创建配对；把配对页面加入目标多维表格的侧边栏插件；在插件中选择列和范围并导入 | 租户允许自定义侧边栏页面，官方 SDK 可读取目标表；配对完成后使用其固定字段和范围 |
| 仅扫码 | 点击打开登录窗口，在独立 Chromium 窗口登录后读取链接 | 当前支持飞书中国站；链接含表和视图；依赖私有网页数据格式，兼容性需实际验证 |

连接器配对链接中的片段包含一次会话的访问码，请在本机使用。浏览器或租户可能限制 HTTPS 飞书页面嵌入本地 HTTP 页面；应按飞书侧边栏开发环境要求配置，不能以关闭浏览器安全机制代替。具体权限、分页保证和仅扫码限制见 [浏览器与接入说明](browser/README.md)。

默认读取所选数据表全部记录；“仅链接视图”以该视图的可读范围为准。仅扫码遇到筛选视图时不能证明全表完整，需要换无筛选视图或 API/连接器。导入期间尽量不要修改表内容。记录按来源 ID 关联，按导入顺序显示，不受并发完成顺序影响。

## 判断与日志

图片结论是“正常 / 异常 / 待确认”。解码、尺寸、亮度、纯色占比、模糊与 BRISQUE 都作为证据；截图、图表和照片不会按统一质量分数一刀切。多图逐张分析后汇总至原行。日志报错本身不直接判定图片异常；AI 未配置、不可用或返回不合法结果时保留离线证据并标为待确认。

直接文本、JSON 和日志文件会保存完整原始字节，另存用于阅读的 UTF-8 文本。网页提取正文；没有可验证的完整结束条件时显示“日志读取不完整”。在设置的日志站点规则中配置域名、令牌头/值、正文 CSS 选择器、下一页选择器、可选结束标记和原文下载入口。令牌值填写完整值，例如 `Bearer …`。

遇到登录页或权限问题，专用浏览器用于手动登录；完成后点击失败行重试。没有权限时登录无法替代授权。页面只能显示近期片段时，应配置原始日志下载入口。超过分页上限、重复分页、后续页面失败都会保留已读部分与原因。浏览器附件/文件下载单个上限为 256 MB，超出会失败而不是静默截断。

长日志按块读取和摘要，详情按需分页加载。网页原始响应、渲染快照和合并正文分别保存，必要时原始内容下载为 ZIP。不要把正文提取结果当作源站后台的完整日志文件。

## 导出与恢复

- Excel 的结果表按原顺序输出全部已导入记录，包含缩略图、结论、摘要和来源链接；处理中或失败行也占一行。
- “图片详情”表保存逐图结论、依据、离线指标与失败原因，通过原行序号和记录 ID 对应主表。
- 完整日志放在隐藏详情表，每块最多 30,000 字符并记录块序号。**Excel 不能直接跳入隐藏工作表**：先右键工作表标签 → 取消隐藏“日志全文”，再点击结果行的跳转链接。原始文件可在网页下载。
- 暂停停止领取新行，正在处理的行会完成；取消保留现有结果及未处理行。失败重试只重置失败/取消行，保持原记录 ID 与序号。
- 服务重启后已导入任务恢复为暂停，处理中的行重新等待。导入未完成的任务会标记导入失败，应重新新建，避免续接到已变化的表快照。
- 同一任务内复用重复图片和成功完整的日志下载。AI 缓存包含图片/日志内容、接口、模型与业务标准；配置变化不会误用旧结论。

## 本机数据

数据目录含 SQLite、设置、任务图片、缩略图、原始日志、模型资源与独立浏览器登录资料。Windows 设置中的 API Key、App Secret、站点令牌通过当前用户的 DPAPI 加密；登录状态由专用浏览器保存。导出文件不含这些凭证。数据目录、虚拟环境和构建产物均在 `.gitignore` 内。

保留数据目录即可保留任务；备份前停止服务。DPAPI 加密的设置通常只能由原 Windows 用户解密，迁移机器后应重新填写凭证和登录。服务仅监听本机回环地址，没有多人账户系统。

离线仅指图片指标可离线计算；飞书读取、远程日志获取与 AI API 仍需要网络。并发默认下载 4、AI 2、浏览器 2，可在设置调整；活动任务期间保存的并发值在全部任务结束后应用。离线检测在独立工作进程执行。高并发会受源站、机器内存和模型限流约束。

## 开发与验证

```powershell
.\.venv\Scripts\python.exe -m pytest -q
Push-Location browser
pnpm test
Pop-Location

# 实际 Chromium + 本机测试站点集成测试（不连接真实飞书）
$env:VIZSENTRY_BROWSER_TESTS = '1'
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.data\browsers"
.\.venv\Scripts\python.exe -m pytest tests\test_browser_source.py -q
```

如运行时不在 PATH，先执行 `. .\scripts\runtime.ps1; Set-VizRuntime -ProjectRoot $PWD`。开发网页可在 `frontend/` 运行 `pnpm dev`，Vite 把 `/api` 代理到本机 8765 后端。后端入口为 `backend/vizsentry/app.py`。

模块：`sources.py` 统一三种来源；`browser/` 提供 Playwright NDJSON 子进程；`connector/` 是飞书 SDK 侧边栏；`engine.py` 管理任务；`database.py` 持久化；`image_analysis.py`、`log_reader.py`、`model_client.py` 封装检测、日志和模型；`exporter.py` 导出 Excel。

测试包括空表、跨页、中文字段、多图/缺图、异常图片、部分日志、登录提示、超时/限流/非法模型结果、缓存、任务恢复及 Excel 长日志重组；另有 1 万 / 10 万行模拟清单、分页与持久化测试。这些规模测试不代表真实图片和模型吞吐量。见 [验收记录](docs/verification.md)。
