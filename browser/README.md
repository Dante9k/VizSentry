# 飞书读取与浏览器日志组件

此目录的 Node.js + Playwright 进程只通过父进程的 stdin/stdout 接收 NDJSON RPC，
不监听网络端口。浏览器使用应用数据目录中的 `browser-profile/`，不读取个人 Chrome
或 Edge 配置。扫码和日志登录在该专用窗口中完成，后续读取复用该会话。

运行 `pnpm install`，然后 `pnpm exec playwright install chromium`。Windows 安装脚本
会统一准备依赖与浏览器。若设置 `PLAYWRIGHT_BROWSERS_PATH`，启动时必须保持同一路径；
`VIZSENTRY_NODE` 可指定 Node 可执行文件。`VIZSENTRY_BROWSER_HEADLESS=1` 仅供测试。

## 三种接入及权限

| 接入 | 所需授权 | 完整性依据 |
| --- | --- | --- |
| 应用凭证 | 飞书应用 App ID/Secret；应用有多维表格读取权限、附件下载权限，且表格授予应用访问 | 官方记录分页的 total、结束标记、唯一 record_id |
| 扫码＋连接器 | 浏览器登录后，在目标 Base 侧边栏加载本地 SDK 页面；租户允许该扩展入口 | SDK 每页最多 200 行；total、pageToken、hasMore；服务端批次顺序和唯一记录校验 |
| 仅扫码 | 在专用浏览器拥有目标表查看权限；完整链接包含 table/view | 固定版本网页读取器的表修订号、recordsNum、分页记录去重及结束标记 |

官方 API 模式解析 `/base/` 和实际指向多维表格的 `/wiki/` 链接。应用的读取权限名及
管理员批准要求以当前飞书开放平台控制台为准；使用字段/记录/媒体下载接口进行诊断。
API 403 或业务错误码通常表示应用权限或表格访问授权未就绪。日志站点令牌与飞书
应用凭证分别配置，飞书 App Secret 不会发送给日志或外部图片地址。
API 附件保留官方返回的 `url`/`tmp_url` 权限参数；缺失时根据表、字段、记录和附件
标识构造官方 `bitablePerm.extra`。租户 Bearer 仅发送至固定的官方 API 域，
跨域下载重定向不会携带该令牌。高级权限说明：
<https://open.feishu.cn/document/docs/bitable-v1/faq?lang=zh-CN>。

仅扫码读取器改自 `lewishezhu-rgb/feishu-bitable-export` 的提交
`d00117fd8f744c09055b62d92415f62ed5999157`；原始源码和 MIT 许可证保存在
`third_party/feishu-bitable-export/`。仅扫码当前支持 `*.feishu.cn`；国际 Lark 地址
请使用 API 或 SDK 模式。

## 范围和已知限制

- “全部记录”模式不会移除视图筛选，也不猜测被隐藏的记录；若当前视图含筛选，
  则要求换成无筛选视图或换用 API/SDK。隐藏列仍可选择，但需有字段读取权限。
- “仅链接视图”允许筛选；如果私有分页接口未提供明确结束标记，会停止导入。
  此时预览总数可能未知，任务不能标为完整或启动分析。
- 私有网页接口不是飞书公开兼容性承诺。数据结构变化、授权异常、记录数不符、重复
  分页位置或分页停止增加记录都会报错。未进行真实飞书表格验收。
- 上游私有记录中的图片必须带可读下载 URL。只有 token、没有 URL 的附件会保留
  原行并记录图片失败，建议使用 API/SDK 重新导入，不能称为图片分析成功。
- 可用的网页图片 URL 在清单导入时按最多四行预取并保存至本机快照；后续分析使用
  快照，避免在超大表导入期间临时 URL 过期。没有获取成功的图片仍保留引用以重试。
- SDK 附件在每行读取时立即保存；如果下载/上传失败，该行保留具体错误，需要在
  连接器重新配对导入，普通分析重试无法重新调用已关闭的 SDK 页面。
- 浏览器读取按导入发现顺序输出；它不承诺重现飞书网页的全部排序展示细节。

## 日志完整性和登录

原始文本或下载文件完整保存。网页仅有正文时标记为 partial。按站点配置正文 CSS
选择器、下一页选择器、可选完成标记或下载链接选择器后，才根据明确的终止条件
判断网页读取完成。第一页找不到下一页控件不会被当作完整日志。

原始首页 HTTP 响应与每页渲染后的 HTML 快照一起保留；合并正文单独保存。渲染快照
不等同于后台日志文件：若网页自身只显示最近若干条日志，仍需配置真实下载入口。
超出分页上限、内容重复、下一页超时或后续读取错误均保留已读取部分并标记不完整。
单次浏览器附件/原始文件下载安全上限为 256 MB，超出时明确失败，不返回截断文件。

登录页/密码框/401/403 会打开专用窗口并返回 login_required；用户完成登录后重试。
站点令牌仅附加到配置 URL 的同一 origin，跨域重定向与资源请求主动移除自定义认证
头。下载按目标域获取浏览器 Cookie，不复制其他域 Cookie。页面和凭证不进入 RPC
诊断输出；登录资料与下载保存在忽略提交的本机数据目录。

## 验证

`node --test reader.test.mjs` 验证链接、筛选和私有响应结构。
`pytest tests/test_sources.py` 验证 API 分页、续期、完整性、连接器配对、持久化和附件。
安装 Chromium 后，设置 `VIZSENTRY_BROWSER_TESTS=1` 运行
`pytest tests/test_browser_source.py`，使用本机测试站点验证实际浏览器 RPC、登录提示、
文本/网页、分页、Cookie 下载；它不替代真实飞书与实际日志站点的验收。
